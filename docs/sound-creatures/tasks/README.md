# LLM実行タスク — おとのいきもの

## 実行ルール

各ファイルは、LLMが1タスクずつ独立して実行できる仕様書である。

- 番号順に1つずつ実行する。
- 前タスクの合格条件を満たし、人の確認が必要なゲートを通過してから次へ進む。
- タスク開始時に対象Issueとこの文書を読み、対象外の変更を行わない。
- 既存の `DiscoveryId` と保存済み発見データを壊さない。
- 各タスクで lint、型検査、関連テスト、必要な手動確認を行う。
- 大きなリファクタリングは同じ変更に混ぜず、必要性を報告して別Issueにする。

## Issue運用

最初から全タスクを実装Issue化しない。統括Issueと現在実行する1件だけを作成し、
レビューで得た知見を次のIssueへ反映する。完了したIssueから次のIssueを1つ作ることで、
未検証の前提がバックログ上で仕様として固定されることを防ぐ。
