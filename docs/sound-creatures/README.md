# おとのいきもの — プロダクト・実装設計

## 1. 目的

「はっけんカード」を、子どもが自分の音の中で出会うオリジナルキャラクター
「おとのいきもの」へ発展させる。

この機能の中心は収集ではない。子どもが試した音の組み合わせに世界が反応し、
あとから「自分はこんなことをしていたのか」と気づく体験をつくる。

> つくる → 何かが起こる → 生き物と出会う → へぇ、なるほど → また試す

発見は行動を釣る報酬ではなく、すでに起きた試行錯誤に名前を与えるものとする。

## 2. 児童向けの言葉

| 現在             | 変更後                    | 備考                     |
| ---------------- | ------------------------- | ------------------------ |
| はっけんカード   | おとのいきもの            | キャラクターそのもの     |
| カードアルバム   | おとのずかん              | 未発見はシルエットで表示 |
| カードをみつけた | おとのいきものと であった | 捕獲・所有ではなく出会い |
| 音楽のことば     | 音楽のことば              | 学びの説明として維持     |

内部の `DiscoveryId`、`card_id`、`user_discovery_cards` は変更しない。
表示上の名称変更のために既存データを移行しないことが重要である。

## 3. 体験の原則

### 3.1 正解を教えない

- 「この音を置けば会える」というレシピを先に見せない。
- 未発見のヒントは、試す方向をそっと示す開かれた文章にする。
- 発見後に初めて、その音の関係と音楽のことばを説明する。

### 3.2 強さや希少性をつくらない

- レア度、強さ、進化条件、経験値、連続ログイン、ランキングを設けない。
- 図鑑の完成率を主目的として強調しない。
- 「全部集めないと損」と感じさせる期間限定・ガチャ表現を使わない。

### 3.3 既存作品を模倣しない

「生き物を見つけて図鑑に載せる」という体験だけを参考にし、特定作品の輪郭、
目、配色、捕獲道具、名称規則、画面構成を再現しない。BeatBubble独自の
「音から生まれた形」をデザイン言語にする。

### 3.4 次の試行につなげる

発見説明は用語の定義だけで終えず、「同じ生き物でも置く場所や高さを変えると、
どんな感じになる？」のような小さな問いで編集画面へ戻す。

## 4. 基本UX

### 未発見

- 生き物の固有シルエットを表示する。
- 名前と色は隠し、`???` と開かれたヒントを表示する。
- シルエットは発見後の画像をCSSで単色化して生成し、別アセットを持たない。
- ヒントは正確な音程・手順を答えとして書かない。

### 初回発見

1. 再生を止める。
2. 対象になった音だけを残して周囲を暗くする。
3. 小さな光や音から生き物が現れる。
4. 名前、性格、現れた理由、音楽のことばを表示する。
5. 子どもが「わかった！」を押すまで閉じない。
6. 元の編集状態へ戻す。

現在の発見モーダルと証拠ハイライトの流れは維持し、カード面を生き物との出会いに
置き換える。

### 再発見

一度出会った生き物では操作を止めない。現在の星に相当する短い反応だけを出す。
将来は、その生き物固有の小さな動きに置き換えられる。

### 図鑑

発見済みのページには次を表示する。

- 生き物の全身
- 名前と短い性格
- 「どうして現れたの？」という平易な説明
- 常時表示される「音楽のことば」
- 初めて出会った日
- 編集へ戻る導線

未発見のページはシルエットと開かれたヒントだけを表示する。

## 5. ドメインとアーキテクチャ

発見判定とキャラクター表現を分離する。

```text
Song
  ↓ 純粋な判定
src/discovery/*
  ↓ DiscoveryId + evidence
src/creatures/*
  ↓ キャラクター表現へ変換
発見演出 / おとのずかん / 将来の相棒
```

### 維持する責務

- `src/discovery/*`: 音楽的な発見、証拠、表示キュー、保存値の検証
- `src/hooks/*`: 発見状態と永続化、再生との接続
- `user_discovery_cards`: ユーザーが発見した `DiscoveryId` の集合

### 新設する責務

`src/creatures/` を表示ドメインとして追加する。

- `catalog.ts`: `DiscoveryId` とアセット、演出種別の網羅的な対応
- `types.ts`: UIが使うキャラクターメタデータの型
- 固有名、説明、alt文、ヒントは `src/lib/i18n.ts` に置く

キャラクターカタログは発見判定を行わず、`Song` に依存しない。逆に
`src/discovery/*` は画像やキャラクター名を知らない。

### アセット規約

```text
public/creatures/<discovery-id>/portrait.png
```

- 透明背景の正方形PNG
- 基準制作サイズ 1024 × 1024
- 96px前後でも輪郭と個性が読める
- UIでは `next/image` を使い、表示領域を先に確保する
- シルエットは同じ画像をCSSで単色化する

## 6. データベース方針

図鑑化まではDB変更を行わない。

- 既存の `user_discovery_cards.card_id` を `DiscoveryId` として利用する。
- 画像、名前、説明、性格はアプリのカタログから解決する。
- テーブル名をUI都合で変更しない。
- 既存ユーザーの発見状態はそのまま図鑑へ引き継がれる。

将来「編集画面へ連れて行く生き物」をユーザーごとに保存する段階でのみ、
選択中の `DiscoveryId` を保存する設定を追加する。その設計は図鑑完成後に別途判断する。

## 7. アートディレクション

- 丸く、触れたくなる形。怖さより不思議さを優先する。
- 1体につき主色2〜3色。小さい表示でも色の塊が混ざらない。
- 音の性質を身体にする。例: 音の距離は耳や腕の間隔、反復は輪の形。
- 目、口、手足の位置や数を少しずつ変え、同じ素体の色違いにしない。
- 武器、文字、ロゴ、現実の楽器そのままの擬人化は避ける。
- 図鑑のシルエットだけでも各個体を判別できる外周を持たせる。
- 線の太さ、光源、質感、目の描き方は全個体で統一する。

`interval_third` の1体を先に制作してアートスタイルを承認し、その後も1体ずつ
確認しながら残りを制作した。2026-08-04に全8体が人手承認済み。個体固有の設定は
[`creature-roster.md`](./creature-roster.md)、共通の視覚規約は
[`style-guide.md`](./style-guide.md) を正本とする。

## 8. アクセシビリティと性能

- `prefers-reduced-motion` では登場演出をフェードに短縮する。
- 色だけで発見済み・未発見を区別しない。
- 発見済み画像には生き物の名前を含むalt文を付ける。
- 未発見画像のalt文で正体を明かさない。
- キーボード操作とフォーカス復帰は現在の発見モーダルの要件を維持する。
- キャラクター画像の読込失敗時にも名前と説明は読めるようにする。

## 9. 将来の「相棒」とAI

図鑑で出会った生き物を編集画面へ連れて行ける将来像は、次の順に分ける。

1. 選んだ生き物が編集画面に居るだけの相棒機能
2. 再生や編集に対して表情・動きで反応する機能
3. 子どもが明示的に呼んだときだけ、試すための問いを出すAI支援

AIは曲を完成させず、音符を自動挿入しない。「終わりだけ変えたらどうなる？」など、
子ども自身の次の一手を促す。曲や行動履歴を継続的に収集せず、その場の曲の状態だけを
必要最小限に扱う。

## 10. 実装順序

実行単位と合格条件は [`tasks/README.md`](./tasks/README.md) に定義する。
各段階は前段のレビュー完了後に開始し、特に最初のキャラクター承認前には量産しない。
